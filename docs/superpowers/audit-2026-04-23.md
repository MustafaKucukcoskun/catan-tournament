## 0. Özet (Executive Summary)

**Kötü haber:**
- UI metni neredeyse **tamamen İngilizce** (spec §11.1 "Turkish UI strings" net bir şekilde ihlâl ediliyor)
- Admin ve Public sayfalar **aynı `<Shell>` + `<Sidebar>` 'ı** kullanıyor — public kullanıcı da sol tarafta "Tournament director · admin · online" kartını, Settings/Live pods nav öğelerini görüyor
- 25 ESLint hatası var (`no-explicit-any`, `prefer-const`)
- `proxy.ts` sadece cookie varlığını kontrol ediyor (session validasyonu yapmıyor), ayrıca Next.js 16'da dosya adı `middleware.ts` olmalıdır — şu anki `proxy.ts` Next.js'in tanıdığı isim değildir
- Spec'in "admin wizard" dediği sihirbaz tek sayfa form (6 adım değil)
- Pairing'de `previousOpponents: new Set<string>()` hep boş — **repeat avoidance pratikte kapalı**
- `detectCutoffTies` tetiklenince sadece `{ cutoffTies }` dönüyor, ama bunu **yakalayacak UI yok** — eleme cutoff tie modal'ı yok
- `localSwapRepair` içinde `rng` kullanıyor ama seed stream'i zaten main loop'ta tüketildiği için deterministik değil
- Session clock (`SessionClock`) ile LiveTimer (`LiveTables` içinde) **sunucu ile istemcide farklı zaman hesaplıyor** → hydration mismatch riski

**İyi haber:**
- Tüm 42 birim testi geçiyor
- `npm run build` başarılı (Next.js 16.2.4 + Tailwind 4)
- Algoritma kütüphaneleri (`distribute`, `pairing`, `bracket`, `tiebreaker`, `recompute`, `generator`, `validator`) spec §6'ya büyük ölçüde uygun ve temiz
- Realtime subscription mekanizması (`useTournamentRealtime`) spec §9'a uygun
- DB şeması spec §4.1 ile nerdeyse birebir

## 4. Bug'lar — Önem Sırasıyla

### 4.1 KRİTİK

#### BUG-1: Swiss pairing repeat avoidance fiilen kapalı
- **Dosya:** `app/actions/match.ts:35-39`
- **Ne yanlış:** Her çağrıda `previousOpponents: new Set<string>()` boş yaratılıyor — yorumda `TODO: populate from history` yazıyor.
- **Etki:** Tur 2+ Swiss pairing'de aynı oyuncular tekrar eşleşebilir, spec §6.2 "soft constraint repeat avoidance" ihlal.
- **Reproduce:** 12 oyuncu, 3 lig turu. Tur 1 rastgele masa, Tur 2 ve Tur 3 hep aynı VP'li oyuncuları masaya sokarsa aynı masaya gelme olasılığı yüksek.
- **Fix:** `generateLeagueRound` içinde mevcut `table_players` + `match_tables` sorgulanıp her oyuncu için önceki tur rakipler Set'i doldurulmalı.

#### BUG-2: Eleme cutoff tie modal UI yok
- **Dosya:** `app/actions/match.ts:211-213` (backend) ve `app/admin/t/[id]/page.tsx:242-262` (form)
- **Ne yanlış:** `advanceRound` tie tespit ederse `return { cutoffTies: ties }` döndürüyor ama çağıran form server action'dan dönen değeri kullanmıyor (`<form action>` redirect olmayan bir server action'ın dönüşünü sadece `useActionState` ile client'ta yakalayabilir).
- **Etki:** Eleme cutoff'ta gerçekten tie varsa, admin butona basar, hiçbir şey olmaz, console'da hata yok, turnuva eleme'ye geçmez. Spec §2.1 #8 must-have ihlali.
- **Reproduce:** 8 oyunculu turnuva, 1 lig turu, elimination=4. Oyuncular 4. ve 5. sırada tamamen aynı VP/wins/vpPercent ile biterse tie tespit edilir ama hiçbir modal açılmaz.
- **Fix:** `advanceRound` çağrısını `useActionState` ile sarmala, tie döndüğünde `<Modal>` aç, admin'in 2 oyuncudan hangisini cutoff içine alacağını seçmesini iste → `resolveTieAtCutoff` action'ı zaten var (`app/actions/map.ts:67-80`).

#### BUG-3: Admin sayfalarında DB session validasyonu yok
- **Dosya:** `proxy.ts:6-12` ve hiçbir `/admin/*` page'de `await isAuthenticated()` çağrısı yok
- **Ne yanlış:** Cookie'de rasgele 64 karakterli hex yazan bir kullanıcı guard'ı geçer, sayfalar DB çağrısı yapmadığı için admin verilerini görür/değiştirir.
- **Etki:** Güvenlik açığı. Pratikte hex cookie brute force çok düşük olasılık (2^256) ama spec §8.2 "Session DB check (hash compare)" diyor.
- **Fix:** Ya `proxy.ts` içinde DB check (Next.js middleware edge runtime'da Supabase çağrısı yapabilir), ya da her admin sayfasında `if (!await isAuthenticated()) redirect('/admin/login')`.

#### BUG-4: `proxy.ts` dosya adı Next.js convention'ı olmayabilir
- **Dosya:** `C:\...\catan\proxy.ts` — `middleware.ts` değil
- **Ne yanlış:** Next.js 16 breaking changes olduğu kabul edilmeli (AGENTS.md uyarısı). Ancak build output `ƒ Proxy (Middleware)` gösterdiğinden Next.js 16'da "proxy.ts" doğru convention olabilir — DOĞRULAMA gerekir.
- **Etki:** Yanlış ise middleware hiç çalışmaz, admin guard devre dışı.
- **Fix:** `node_modules/next/dist/docs/` okunmalı ve doğrulanmalı. Context7 MCP ile Next.js 16 middleware docs çekilmeli. Emin olunmazsa `proxy.ts` → `middleware.ts` rename.

#### BUG-5: Eleme 2. tur ve sonrası "körü körüne" 4'lü gruplama
- **Dosya:** `app/actions/match.ts:312-335` `advanceEliminationRound`
- **Ne yanlış:** Kazananlar kenar toplamayla gelip `for (let i = 0; i < winnerIds.length; i += 4)` — bu spec §6.3 "tiered random seeding" değil, **hatlatılmış sıra**. 16 oyuncudan 4 kazanan çıktıktan sonra finale gidiliyor (4 oyuncu = 1 masa → bu durum OK) ama 64 → 16 kazanan → 4 masa senaryosunda yeniden tier seeding yapılmalı.
- **Etki:** Büyük bracket'lerde adil seeding yok. 64 kişilik senaryoda özellikle hissedilir.
- **Fix:** `advanceEliminationRound` içinde kazananları tier sıralamasıyla `seedBracket` çağrısına benzer bir mantıkla yeniden grupla.

#### BUG-6: localSwapRepair reverse logic yanlış
- **Dosya:** `lib/map/generator.ts:47-78`
- **Ne yanlış:** `localSwapRepair` içinde revert yaparken (satır 71-74) tmp2'yi okuma sırası yanlış. Kodu izlersek:
  - Line 60: `tmp = {a.resource, a.token, a.pip}` (`a`'nın ilk hali)
  - Line 61-62: a'ya b'nin değerleri, b'ye tmp (yani a'nın ilk hali) yazılıyor → swap OK
  - Line 71-74 (revert): `tmp2 = {a.resource, ...}` — ama **a şu an b'nin ilk hali**, yani tmp2 = b'nin ilk hali! Sonra a'ya b'nin şu anki değerleri (= a'nın ilk hali) yazılıyor, b'ye tmp2 yazılıyor (= b'nin ilk hali). **Sonuç: bu reverse DOĞRU** — çünkü swap sonucu a↔b ilk haline döner. Bu yanlış bir bug değil, sadece kodu okurken kafa karıştırıcı.
- **Verdict:** Yanlış alarm, kod çalışıyor. Ama okunabilirlik düşük → refactor tavsiye edilir.

```ts
const { data: prevTables } = await sb.from('match_tables')
  .select('id, round_id')

  .select('match_table_id, player_id')
  .in('match_table_id', prevTables.map(t => t.id));
// Her player için previousOpponents Set'i kur (aynı masada oynamış diğerleri)
const prevOpponents = new Map<string, Set<string>>();
for (const tp of prevTPs) {
  const tableMates = prevTPs.filter(x => x.match_table_id === tp.match_table_id && x.player_id !== tp.player_id);
  if (!prevOpponents.has(tp.player_id)) prevOpponents.set(tp.player_id, new Set());
  for (const mate of tableMates) prevOpponents.get(tp.player_id)!.add(mate.player_id);
}
// Sonra pairingPlayers'a yükle:
previousOpponents: prevOpponents.get(p.id) ?? new Set()
```
